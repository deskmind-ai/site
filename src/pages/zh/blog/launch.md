# 小到能在你的 Mac 上跑，<br>聪明到知道该问你

DeskMind 是一个全栈开源、在你 Mac 上替你操作电脑的 AI。你写下目标，它看屏幕、用本机的小模型决定每一步，然后操作你的应用。目标可能有两种理解时，它先问你，不瞎猜。

**先说结论**
- **小，而且就在你的 Mac 上。** 0.8B 判断每一步，难的交给 4B 复核，两个模型都是 8 位 MLX，在 Apple 芯片上本地运行，不走云端，也不按次付费。
- **选择，不是猜。** 每一步都是一道选择题，每个选项都有概率。正因为有概率，它才能把没把握的步骤交给大模型、遇到歧义先问你、没做完不说完成。
- **在真实桌面上测。** 我们自己的 13 个 macOS 任务、每个跑 3 次，经 App、在一台 M4 Pro 上：发布版 39 次全部通过，没有一次没做完就说完成。样本不大，哪里还不行，下面都写了。
- **从眼到手，全部开源。** 看屏幕的模型、做决策的模型、操作桌面的执行层、Mac App 和评测，全在 GitHub 上，代码 Apache-2.0。

## 为什么要“先问”

大多数电脑操作 AI 出错时是悄悄出错的：挑一个看起来合理的选项，继续往下做，最后报告成功。在桌面上，“看起来合理”常常是错的文件、错的那一行、错的收件人，等你发现已经晚了。

我们演示里的任务是：“在 records.txt 里找到 Lisa Wong 的订单，追加进 ledger.csv。”文件里有两笔 Lisa Wong 的订单。会猜的模型随便写一笔，然后说完成；DeskMind 会停下来问你要哪一笔，按你选的写入、保存、收尾。问一句的成本是一句话，猜错的成本是一本错账。

要在该问的时候问，模型得知道自己什么时候没把握。这是整个设计的核心。

## System One：每一步都是选择题

一个桌面步骤会被拆成几道带类型的问题：做什么操作、点哪个元素、填什么值。每道题都列出选项，用字母编号。决策模型 Brain 在答案位置读取这些字母的 logits，一次前向计算就给出每个选项的概率。它从不自己写自由文本，所以没有要解析的输出，也做不出列表之外的动作。

这些概率有三个用处：
- **分流。** 0.8B 先答。把握低于发布版门槛（0.96），或者这一步错了代价大（宣布完成、撤销、少见的快捷键），就交给 4B。
- **提问。** 执行层发现有两条记录都匹配时，“问用户”就是选项之一，模型会选它。
- **不提前收工。** 运行结束前，执行层会检查最终状态，模型说“完成”必须经得起这道检查。

概率是模型的把握，不是保证。选择题只避免了格式错误，避免不了判断错误：正确选项不在列表里，或者模型很自信地选错，这一步照样会错。

Brain 实现的是 `/v1/systemone` 请求格式，任何 agent 都可以在本机通过 HTTP 调用它。

## 速度如何

说实话：0.8B 有把握时很快，没把握时要几秒。
- 0.8B 自己回答的步骤：中位数约 0.5 秒。
- 交给 4B 复核的步骤：中位数约 3.6 秒；这一版大约 70% 的步骤会交给 4B。
- 全部步骤合起来：中位数 2.85 秒，最慢的 5% 要 9.8 秒（真实桌面上 208 次决策）。

原因是我们训练时犯的一个错误（下文第 6 条）：0.8B 的把握挤在很窄的区间里，门槛只要能保证它不出错，大多数步骤就都会被送上去。把快路径拉宽，是下一轮的主要目标。

## 成绩，附样本量

| 测什么 | 结果 | 范围 |
|---|---|---|
| 真实桌面，bench v25 | **39/39 通过，0 次没做完就说完成** | 13 个任务 × 3 次，中文界面，一台 M4 Pro，经 App，路由门槛 0.96 |
| 视觉定位，ScreenSpot-Pro（1,581 题） | App 实际设置下 **50.9%**（4 位 MLX，图片 ≤ 200 万像素）；GPU、原始分辨率下 67.7% | 差距主要来自分辨率：400 万像素在 300 题子集上是 59.0%，但慢 2.5 倍 |
| JevBench v1.4.2 公开题 | 4B **0.835**（193/231） | 只是公开题，密封评测已提交。全场的公开题分数普遍明显高于密封题，所以我们不拿它和别家比 |

希望你注意的几点：
- 有一个任务（把一段中文原样写进文件），3 次都是文件写对了，但模型一直没说“完成”，把步数预算用光了。评分看最终状态，所以算通过。
- 评测任务是我们自己出的。题目、评分程序和逐题结果都公开，你可以自己跑。
- 还做不好的：抄写长表格（超过约四行）或按条件筛选的行，根据收据图片填写报销单。

## 一路上踩过的坑

前后大约二十轮训练，教会我们的更多是怎么评测，而不是怎么训模型。下面每一条都花掉了我们一轮：

1. **提示词的形状泄露了标签。** “完成”类训练样本只有“做什么操作”这一道题，其他样本还有目标题。模型学会了：提示短，就说完成。现在每条训练样本都和真实请求一模一样。
2. **标注程序只能标它看得到的东西。** 一次填写成功后，记录下来的状态里有个字段看起来还是空的，于是标注程序教会了每个模型再填一遍。
3. **从目标文字里学到的捷径。** 目标里常带一个格式示例，模型学会了“答案永远不是那个示例”，恰恰在答案就是示例时错了。靠反例修好。
4. **离线留出集抓不到捷径。** 从同一批轨迹里切出来的留出集，和训练集有同样的捷径。每一轮都修好了上一个错误、又引入一个新的：有一轮修好了顺序问题，却在顺序错的时候说完成；下一轮修好这个，又替换掉了表头。现在每次上真机之前，离线关卡都会把我们收集过的所有探针和真实失败，拿新旧两版重放一遍。
5. **长得像的状态要成对训练。** 模型把录音室版当成了要找的现场版。用成对数据训练（同一个界面，只差那个决定性的细节），一轮就修好了。
6. **固定的软标签会压扁把握。** 我们用平滑到 0.95 的规则标签训练 0.8B，结果它的把握全挤在 0.94–0.97 之间，路由分不清哪步简单哪步难。这就是现在 70% 的步骤要交给 4B 的原因，下一轮会改成蒸馏 4B 的真实概率分布。
7. **“先问”要专门训练，也要一直守住。** 有一轮从没学过提问，于是自信地写错了行还宣布成功；后来又有一轮丢掉了一部分提问能力，直到我们把路由门槛从 0.94 调到 0.96。现在“先问”是关卡里单独的一项检查。

## 接下来

- **更快：** 校准好的 0.8B，让更多步骤留在快路径上。

## 怎么试

**Mac App**（macOS 15 及以上、Apple 芯片，运行时约占 7 GB 内存）：从[最新发布页](https://github.com/deskmind-ai/app/releases/latest)下载 DMG。第一次运行会下载约 5.3 GB 模型，Hugging Face 慢的话会自动改用 ModelScope。然后试试内置的示例，或者写你自己的目标。按 ⌘. 停止；碰一下鼠标或键盘就会暂停。

**把 Brain 当决策 API 用：**

```bash
git clone https://github.com/deskmind-ai/brain && cd brain
uv sync --extra mlx
uvx modelscope download --model gxcsoccer/brain-4b --revision g18b-q8 --local-dir models/brain-4b
uv run deskmind-brain-serve --predictor mlx:models/brain-4b --port 8793 --two-stage
curl -s localhost:8793/v1/systemone -H 'Content-Type: application/json' -d @examples/request.json
```

文档：[deskmind.dev/zh/docs](https://deskmind.dev/zh/docs/?ref=zhihu)。
