# 小到能在你的 Mac 上跑，<br>聪明到知道该问你

*一边训模型、一边写 harness：我做本地 Computer Use Agent 的三周*

我一直想要一个敢放心交给它操作自己电脑的 AI，也就是现在常说的 Computer Use Agent。试过的几个方案都能用，有时还挺惊艳，但有三件事一直让我不踏实：

- **隐私。** 每一步都要把我的屏幕截图发到别人的服务器上：邮件、文件、屏幕上碰巧开着的任何东西。
- **贵。** 一个任务几十步，每一步都要把屏幕和历史重新发一遍。只是点个按钮，token 账单却涨得很快。
- **慢。** 最好的模型经常要排队，每一步都是一次云端往返，本该一分钟的任务要等好几分钟。

所以我想试一个问题：如果把模型外面那层代码（harness）专门为它设计，一个小模型在本地能做掉多少？大概做不了全部。但只要本地能处理大多数步骤，剩下的交给更大的模型，这种混合方案就能让屏幕留在本机、每一步几乎不花钱，而且足够快。

DeskMind 就是这个问题做了三周之后的样子：一个在 Mac 上运行的开源 Computer Use Agent（让 AI 替你操作电脑）。本机的小模型看屏幕、决定每一步、操作你的应用；目标可能有两种理解时，它先问你，不瞎猜。

## 先做眼睛，再做大脑

我是从“看”开始的。很多应用不提供辅助功能信息，agent 只能从像素里找出“提交按钮在哪”。这就是 **Eyes**，一个 4B 的视觉定位模型。这也是我第一次做模型后训练：先 SFT，再 RL；先在 Tinker 上跑，后来换到阿里云 PAI，最后自己按小时租显卡。

后来 Jev 横空出世，决策模型一下子火了。它的思路很漂亮：不让聊天模型写出下一步动作，而是问它一道带类型的选择题，读出每个选项的概率。快、好解析，而且知道自己什么时候没把握。但它只有云端接口，我没法把一个云端依赖放在本地 agent 的正中间。于是我试着自己训一个本地的，这就是 **Brain**：Qwen3.5 的 0.8B 和 4B 加 LoRA，在 Apple 芯片上用 8 位 MLX 运行，接口用同一套`/v1/systemone` 请求格式。

把它们串起来的是 macOS 执行层 **Hands**；**Mac App** 把这一切装进一个应用；**Bench** 是我们用来测它的一组真实桌面任务。五个部分全部开源。

## 对我来说最大的变化：模型不再是黑盒

以前做 agent，基本都是围着一个改不了的模型写 harness。模型在某件事上系统性地出错，能用的手段只有改提示词和重试。

两边都握在自己手里之后，事情变了：模型可以照着 harness 的需要来训，harness 也可以补上模型的短板。这几周的几个例子：

- **先问，不猜。** 目标里的记录匹配到两行时（“把 Lisa Wong 的订单加进去”，而她有两笔订单），harness 会在选项里加上“问用户”，模型被训练去选它。这件事单靠任何一边都做不到。
- **不提前收工。** 模型说完成，harness 先核对文件或应用的最终状态再接受。模型也在几乎一样的成对样本上训练过（保存了 / 没保存、最后一行缺了），所以它说“完成”本来就很少出错。
- **在模型弱的地方加护栏。** 目标只要求追加一行，模型却想替换整篇文档时，harness 会拒绝并告诉它原因。这次拒绝又成了下一轮的训练数据。
- **分清长得像的东西。** 让它播放一首歌的现场版，它总选录音室版。我们用成对数据训练（同一个界面，只差那个决定性的细节），一轮就修好了。

这种模型和 harness 一起设计的方式，才是我觉得这个项目最大的收获，比任何一个分数都重要。

## 用 Claude Code 做出来的

说到怎么做出来的，我得老实讲：没有 Claude Code，我一个人不可能在三周里完成这么完整、这么多探索的项目：五个仓库、一个 Mac App、一套评测，还有大约二十轮训练。好几个 Claude Code 会话同时在干活：一个负责模型和训练，一个负责 harness、App 和评测，彼此通过一个私有仓库里的 issue 协作。大部分代码是它们写的，训练和真机测试也是它们跑的，关卡也是它们守着的。我做的是决定做什么、测什么，以及什么样才算可以发布。

## 一步是怎么决定的

一个步骤会被拆成几道带类型的问题：做什么操作、点哪个元素、填什么值。Brain 一次前向计算读出各个选项字母的 logits，给出每个选项的概率。它从不写自由文本，所以没有要解析的输出，也做不出列表之外的动作。

这些概率有三个用处：
- **分流：** 0.8B 先答；把握低于发布版门槛（0.96），或者这一步错了代价大，就交给 4B。
- **提问：** 两个选项都说得通时，“问用户”就是其中一个选项。
- **不提前收工：** 模型说“完成”，必须经得起 harness 对最终状态的检查。

概率是模型的把握，不是保证；选择题避免的是格式错误，避免不了判断错误。正确选项不在列表里，这一步照样会错。

## 对照最初想解决的问题

- **隐私：基本做到。** 每一步决策都在你的 Mac 上完成，模型服务只监听 `127.0.0.1`。App 自己联网只是为了一次性下载模型；它操作的应用当然还会照常联网。
- **成本：做到了。** 每一步都不按 token 计费。成本挪到了训练上：三周里租显卡、调用训练 API 和标注，一共约 600 美元。对我来说，这是一笔值得的学费。
- **速度：还没做到。** 0.8B 有把握时，一次决策约 0.5 秒；但这一版约 70% 的步骤要交给 4B，每次约 3.6 秒，所以决策中位数是 2.85 秒，最慢的 5% 要 9.8 秒。原因是下面会讲的一个训练错误，修好它是下一轮的主要目标。
- **混合方案：做了一半。** 0.8B → 4B 的路由是本地这一半。把最难的步骤交给云端模型已经在设计里（一个你自己开启的升级层），但App 还没有这样做。

## 成绩，附样本量

| 测什么 | 结果 | 范围 |
|---|---|---|
| 真实桌面，bench v25 | **39/39 通过，0 次没做完就说完成** | 13 个任务 × 3 次，中文界面，一台 M4 Pro，经 App |
| 视觉定位，ScreenSpot-Pro（1,581 题） | App 实际设置下 **50.9%**（4 位 MLX，图片 ≤ 200 万像素）；GPU、原始分辨率下 67.7% | 差距主要来自分辨率：400 万像素是 59.0%，但慢 2.5 倍 |
| JevBench v1.4.2 公开题 | 4B **0.835**（193/231） | 只是公开题，密封评测已提交 |

有一个任务 3 次都是文件写对了、模型却一直没说“完成”，把步数预算用光了；评分看最终状态，所以算通过。评测任务是我自己出的，题目、评分程序和逐题结果都公开，你可以自己跑。还做不好的：抄写超过约四行的表格，根据收据图片填报销单。

## 二十来轮训练教会我的事

1. **难的是评测。** 每一轮都修好了上一个错误，又悄悄引入一个新捷径：有一轮修好了顺序问题，却在顺序错的时候说完成；下一轮修好这个，又替换掉了表头。从同一批轨迹里切出来的留出集，和训练集有同样的捷径。最后管用的，是一道离线关卡：每次上真机之前，把我们收集过的所有探针和真实失败，拿新旧两版重放一遍。
2. **提示词的形状会泄露标签。** “完成”类样本的题目比别的少，模型就学会了“提示短就说完成”。现在每条训练样本都和真实请求一模一样。
3. **标注只能标它看得到的东西。** 一次填写成功后，记录下来的状态里有个字段看起来还是空的，于是标注程序教会了每个模型再填一遍。
4. **固定的软标签会压扁把握。** 我用平滑到 0.95 的标签训 0.8B，它的把握全挤在 0.94–0.97 之间，路由分不清哪步简单哪步难。这就是现在 70% 的步骤要升级的原因；下一轮改成蒸馏 4B 的真实概率分布。
5. **“先问”要专门训练，还要一直守住。** 有一轮从没学过提问，于是自信地写错了行；后来又有一轮丢掉了一部分，直到重新调了路由门槛。现在“先问”是关卡里单独的一项。

## 怎么试

**Mac App**（macOS 15 及以上、Apple 芯片，运行时约占 7 GB 内存）：从[最新发布页](https://github.com/deskmind-ai/app/releases/latest)下载 DMG。第一次运行会下载约 5.3 GB 模型，Hugging Face 慢的话会自动改用 ModelScope。按 ⌘. 停止；碰一下鼠标或键盘就会暂停。

**在你自己的 agent 里用 Brain：**

```bash
git clone https://github.com/deskmind-ai/brain && cd brain
uv sync --extra mlx
uvx modelscope download --model gxcsoccer/brain-4b --revision g18b-q8 --local-dir models/brain-4b
uv run deskmind-brain-serve --predictor mlx:models/brain-4b --port 8793 --two-stage
curl -s localhost:8793/v1/systemone -H 'Content-Type: application/json' -d @examples/request.json
```

文档里有一个 30 行的客户端示例：[deskmind.dev/zh/docs](https://deskmind.dev/zh/docs/?ref=zhihu)。
